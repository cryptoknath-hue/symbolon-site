Specification

Prototype. No public network, no token in circulation, nothing for sale. This document describes the mechanism as implemented, including what it does not solve.

A French version of this document is kept at SPEC.fr.md.

Proof of work (AuxPoW)

A block at height h is valid if, and only if:

  1. aux_hash = SHA256(aux_blob) and aux_blob is the canonical serialisation (sorted JSON) of a BlockHeader {version, height, prev_hash, timestamp, difficulty, miner_address, tx_root}.
  2. prev_hash is the current tip, height = tip + 1, difficulty = next_difficulty().
  3. The Monero blob parses; its coinbase carries a 0x03 merge mining tag giving (n_aux_chains, aux_nonce, merkle_root) in the standard merge mining format.
  4. slot = SHA256(chain_id | aux_nonce_le32 | 'm') % n_aux_chains and the merkle proof (Keccak-256, Monero's tree) links aux_hash to merkle_root at that exact slot — which is what stops anyone mining two versions of the same chain.
  5. pow = RandomX(hashing_blob, seed_hash) computed by monerod (calc_pow) satisfies int_le(pow) * difficulty <= 2^256 - 1. RandomX does not hash the full block the pool sends, but its hashing blob: header (up to and including the nonce) + merkle root of [coinbase_hash] + tx_hashes + leaf count. The coinbase hash follows Monero's v2 transaction rule: Keccak(H(prefix) || H(0x00) || 0^32), a coinbase's RingCT base being of the null type. Passing the whole block to calc_pow returns a plausible-looking but wrong hash, and every solution is rejected.
  6. miner_address is a valid address for the network, and the block's body (its transactions) reproduces tx_root. Since the body is never sent to the pool, the node finds it in the template it handed out: a forgotten template is a lost solution (see below).

Timestamps: timestamp <= now + 2h and >= tip.timestamp - 2h.

Accounts, addresses, transactions

An account model, not UTXO. An address is <network prefix> || base58(ed25519_pubkey || checksum), with the prefix (sbll locally, sblt on testnet) feeding the checksum: an address from one network is invalid on the other.

A transaction {version, sender, recipient, amount, fee, nonce, payload, signature} is valid if:

  1. amount > 0, fee >= 0, amount + fee fits in 64 bits, sender != recipient;
  2. both addresses belong to the network;
  3. signature is an ed25519 signature over the fields excluding the signature (sorted JSON), verified with the public key extracted from sender;
  4. nonce is exactly the sender account's counter — it prevents replay and fixes ordering;
  5. the balance covers amount + fee.

txid = SHA256(fields excluding signature): ed25519 being deterministic, the signature adds no malleability.

tx_root is the merkle root of the txids in order, RFC 6962 construction over SHA-256 — not Monero's tree, which stays in merkle.py for the merge-mining side only. Two properties are worth naming, because they are the reason for not reusing the tree we already had:

  • Domain separation. A leaf is SHA256(0x00 ‖ txid), an internal node SHA256(0x01 ‖ left ‖ right). Without it an internal node can be presented as a leaf, and one could prove the inclusion of a "transaction" that is not one.
  • No duplication of the last leaf. The tree splits at the largest power of two strictly below the leaf count, so two distinct bodies cannot share a root (Bitcoin's CVE-2012-2459).

An empty block commits to 32 zero bytes. get_tx_proof returns {index, count, path, header}: a client holding only the header recomputes the root from (txid, path, index, count) and compares it to tx_root. The path's expected length is imposed by (index, count), so a proof cannot be rearranged, padded or truncated.

Applying a block is atomic in SQL: for each transaction, debit amount + fee and increment the sender's nonce, credit amount to the recipient; then credit the miner with block_reward + the block's fees.

The parent Monero block

The Monero block supplied must be well formed, carry our tag at the right slot, and have a sufficient RandomX hash. Nothing more: it does not have to be a block Monero accepted.

This is a decision, not an oversight. Requiring a genuinely accepted block is incompatible with merge mining: a solution meets our difficulty, not Monero's, so barely one Symbolon block in a thousand would be a real Monero block. And requiring the parent to be "known to our monerod" would make our consensus depend on each node's local view of the Monero chain, orphans included: two nodes could disagree on the validity of the same Symbolon block. Namecoin and other auxiliary chains make the same choice, for the same reason.

The consequence, not to be hidden: Symbolon's security is its own difficulty, not Monero's hashrate. Anyone can mine Symbolon with dedicated RandomX hashrate, without going through Monero or a pool. Merge mining makes mining free for those already mining Monero; it does not transfer Monero's security to Symbolon. A 51% attack on Symbolon costs Symbolon's difficulty.

Chain identity (chain_id)

The merge mining unique_id: exactly 32 bytes, as the merge mining format requires. v1: chain_id = Keccak256("symbolon-<network>-v0"), fixed at genesis and checked at startup (NetworkParams.__post_init__). It fixes the chain's slot in the merkle tree: changing it separates the chain permanently from every existing instance (a deliberate hard fork).

Difficulty

LWMA-1 over a 60-block window, targeting 60 s (1 s on the local network, for tests): each interval is weighted by its rank, the most recent weighing most.

  • an interval is capped at 6T: one very late block cannot collapse the difficulty on its own;
  • a timestamp going backwards counts as 1 s, never as a negative interval;
  • the weighted sum has a floor of N²T/20: a burst of instant blocks cannot blow up the target;
  • final floor at min_difficulty.

next = average_difficulty × N(N+1)T × 99 / (200 × weighted_sum). The 99/100 factor is the bias correction from the reference CryptoNote variant.

Emission

reward = max((supply_target - emitted) >> 20, tail_reward), plus the block's fees, credited to miner_address. The reward is not in the header: each node recomputes it from the supply already emitted, which is stored block by block.
Supply targeted before the tail 18,000,000 SBL
First block reward 17.166 SBL
Perpetual tail 0.35 SBL per block (~184,000 SBL/year)
Tail begins around year 8
Service share +40% of the epoch's emission, on top, when nodes are paid
Premine, presale, founder allocation none

With one-minute blocks, >> 20 reproduces Monero's curve exactly in wall-clock time (>> 19 on two-minute blocks). The tail never stops: a chain whose purpose is to pay for a continuous service cannot stop emitting without ceasing to pay.

The share meant for node operators is added to the miner's reward rather than taken out of it: switching the service on takes nothing away from those who mine. It is paid at the end of each epoch (see "Payout epoch"), and the 40% ratio remains open to discussion.

Service node registry

A transaction carries an optional payload. Without it, it is a transfer. With it, it is a registry operation, always targeting its own account (recipient == sender).

Operation Effect
{"kind": "register", "endpoint": …} locks amount as collateral (≥ min_collateral) and binds the endpoint to the address
{"kind": "unregister"} returns the collateral after collateral_lock blocks (amount must be zero)
{"kind": "proof", "round", "signature"} a self-submitted proof of service for that round
{"kind": "attest", "round", "node", "nonce", "signature"} an auditor's probe that got an answer
{"kind": "report", "round", "node"} an auditor's report that nobody answered

The endpoint must be a hidden service. Tor v3 ([a-z2-7]{56}.onion) or I2P ([a-z2-7]{52}.b32.i2p). No clearnet form is acceptable: the "Tor and I2P only" rule lives in consensus, not in a statement of intent.

One address registers one node; one endpoint is taken once. The collateral leaves circulation for as long as it is locked. The same rules apply on entry to the mempool and on block validation, so an impossible operation is refused immediately rather than silently dropped later.

A reorganisation undoes registrations like everything else: the undo journal keeps both the entries created and the entries removed.

Proof of service

A Tor v3 address is an ed25519 public key: base32(key || checksum || version). Consensus extracts the key, verifies the checksum, and uses it to authenticate proofs. An I2P b32 address being a hash of a destination rather than a signing key, an I2P endpoint must declare its key at registration — one notch weaker, and it has to be said plainly.

Each round, a node's challenge derives from the chain:

seed          = Keccak256(round_block_hash || node_address)
monero_height = that block's monero height − (seed[0:4] mod 1000)
digest        = SHA256(the 4 consecutive Monero blocks from that height)
answer        = Keccak256(digest || node_address || round_block_hash)

The operator signs answer with its service key and submits a proof transaction. The validator recomputes everything itself: the challenge from its own chain, the answer from its own monerod, then verifies the signature.

SHA-256 for the bulk — it is native code — and Keccak only for the final binding, over a few dozen bytes, since our Keccak is pure Python.

Three properties follow:

  1. A forged positive is impossible — it would take the hidden service's private key.
  2. Whoever carries the proof has no power over it: not an oracle, just a relay. That is what escapes the classic problem of the unverifiable audit.
  3. Replay is impossible: one proof per node per round, within a 60-block window, and never before registration.

The Monero block range is drawn from the thousand preceding the round, so a pruned node can still verify it.

A self-submitted proof establishes that the operator holds its key, holds the Monero chain and was alive. It does not establish that anyone could reach it — hence the probe.

Auditor probes

Each round, registered nodes are arranged in a ring: order = sort by Keccak256(round_block_hash || address). Everyone audits its five successors, so everyone is audited by its five predecessors. Neither the audited nor the auditor decides, the ring turns every round, and the load is exactly the same for all — nobody is overloaded, nobody forgotten.

The ring costs one sort per round where a per-node draw cost one per node. That is what makes checking missed duties computable at the end of an epoch. Auditors are themselves registered nodes: they have collateral at stake.

On a small registry you cannot appoint more auditors than there are other nodes: the auditor count and the quorum adapt (min(5, N−1) and min(3, auditors)).

The auditor reaches the endpoint, sends a nonce anchored to the round's block — its first eight bytes are those of that block's hash, the rest is its own draw — and the node returns:

answer = Keccak256(digest || node || round_block_hash || auditor || nonce)

signed by the service key. The auditor publishes {"kind":"attest", round, node, nonce, signature}.

The auditor's nonce is what makes this work. Without it, the node could compute the answer offline and would never need to be reachable. With it, producing the signature means having received the probe — having answered at the endpoint.

And the window is held by consensus. A signature carrying that anchor cannot have been produced before that block existed, and a probe is only admissible within the following ten blocks. The answer was therefore born inside an interval the chain bounds itself, rather than one vouched for by whoever held the stopwatch. The chain still measures neither bandwidth nor latency — it bounds roughly ten minutes, not a millisecond — but it no longer trusts the auditor on that point.

The Sybil cost comes from there. Answering means holding the block range and serving it to each of the five auditors. One machine can hold the chain once for a thousand identities; it cannot serve that range a thousand times inside the window.

The absence report

An auditor that cannot reach a node has nothing to sign: an absence cannot be proven. It files a report instead — "I probed, nobody answered". Nothing in it is verifiable, and that is acknowledged: what frames it is not cryptography but the draw and the count.

Without that report the mechanism punished honesty: an auditor discovering a dead node had no way to say so and looked like a shirker. Filing a report counts as a duty fulfilled.

A round counts as available when at least three of the five auditors attested and at most one reported an absence. That second condition changes the arithmetic of collusion: with three accomplices out of five, the two honest auditors report the absence, dissent exceeds the cap, and the round does not count. Four accomplices out of five are now required.

For a fraction f of the registry controlled by an attacker, the probability that a round falls to it goes from P(≥3 of 5) to P(≥4 of 5): at f = 0.5, from 50% to 19%.

Symmetrically, crying absence is a fault when a strong majority did reach the node: beyond two contradicted reports in an epoch, the auditor is penalised like a shirker. Without that, crying absence would be enough to deprive a competitor of its rounds.

A lone lying auditor can therefore do nothing in either direction: it cannot forge a positive (it would need the service key), and one report alone does not sink a round.

Payout epoch

Every service_epoch blocks (720, about 12 hours), the epoch's closing block pays the service share. The amount is not in the header: it derives entirely from chain state, so every node computes the same figure.

pot          = current_reward × service_epoch × 40%
auditor_pot  = pot × 20%
node_pot     = pot − auditor_pot
  • Availability: each node receives node_pot × its_attested_rounds / total_rounds, capped at 15% of the node pot. That cap is this version's only brake on Sybil: multiplying identities does not multiply the share indefinitely.
  • Audit work: each auditor receives auditor_pot × its_probes / total_probes. Auditing is therefore paid, which stands in — for now — for punishing those who do not audit.
  • What is not allocated — caps, rounding, no registered nodes — is simply never emitted. No pot accumulates anywhere, so there is nothing to govern and nothing to divert.

The payout adds to the miner's reward rather than removing from it. The consequence to own: when nodes are registered and available, real emission exceeds the 18 M target by up to 40%. The 18 M describes the mining curve, not the final supply.

The payout belongs to the epoch's closing block: a reorganisation undoes it along with that block, and the new branch's own closing block pays in turn.

Penalising a failing auditor

At each epoch end, the ring is recomputed over a sample of rounds (8 per epoch, spread out) and, per auditor, duties assigned and duties fulfilled are counted. Below 50% of duties fulfilled, 5% of the collateral is burnt.

Burnt, not paid out: nobody should have an interest in another being punished. If the collateral falls below the minimum, the node leaves the registry and the remainder goes back to its operator — keeping a struck-off node's deposit locked would protect nothing.

The 720 rounds are not all re-checked: the cost would be prohibitive. The sample is enough to tell someone working from someone doing nothing, and since the draw is public but unpredictable, nobody knows in advance which rounds will be checked.

Auditor diversity

Over an epoch, the ring eventually sends an honest node auditors from across the registry. A node attested only by the same narrow circle is either barely reachable or surrounded by accomplices — either way it earns nothing. A node is paid for availability only if distinct auditors attested it over the epoch ≥ 50% of the registry.

That is what makes collusion sterile below half the registry: an attacker holding a fraction f can never present more than f distinct attesters for its own node.

(The rule assumes the epoch is long enough for an honest node to meet that many auditors: 720 rounds × 5 auditors gives 3,600 slots, which covers registries up to a few thousand nodes. A larger registry would need a longer epoch or a lower ratio.)

What remains

An operator colluding with four of the five auditors the ring hands it, and holding half the registry, can still fake reachability. And it is a losing trade:

Share of the registry held 30% 50% 60% 70%
Rounds it can fake 3.1% 18.8% 33.7% 52.8%
Share of the pot it captures 0% 15.8% 33.6% 55.2%

Below half, the diversity rule zeroes it out. At half, fifty percent of the collateral buys under sixteen percent of the pot. The attack only pays past roughly sixty percent — the threshold every proof-of-work and proof-of-stake chain lives with.

The worst case is also bounded. A colluder can claim availability it does not have, which dilutes what honest operators are paid. It cannot steal a balance, rewrite the chain, forge a block, or affect Monero in any way. This is subsidy fraud, not a chain attack.

Removing it entirely would mean a trusted party deciding who is reachable — the very thing this design exists to avoid. So it is reduced, quantified, made unprofitable, and stated. Not solved.

Cannot verify is not invalid

Verifying a proof of service means reading Monero blocks. A node still syncing, or whose monerod has pruned the range a challenge names, cannot decide whether the proof holds.

Treating that as invalid would be a consensus bug of the same family as requiring an accepted parent block: two honest nodes would split on the same block because of a local, temporary condition, and the one that is behind would ban the peer that sent it.

So the two outcomes are distinct types. ValidationError means the block is wrong and its sender is at fault. Unverifiable means this node is not in a position to judge: it does not apply the block, does not mark it invalid, does not penalise the peer, and will decide once its monerod has caught up. The same holds for a transaction carrying a proof — it is neither accepted nor relayed, and its sender scores nothing.

A node whose monerod cannot cover the lookback window therefore stops following the chain rather than forking away from it. That is the intended behaviour: a node that cannot check should not pretend to.

Peer-to-peer network

TCP, JSON messages prefixed by their length on 4 bytes, 4 MB maximum.

Handshake — each peer announces protocol, network, chain_id, genesis, params, its node_id, its height and its cumulative work. The connection is refused if any of them differ, or if the node_id is our own (connecting to ourselves).

params is NetworkParams.digest(), a hash of the whole consensus parameter set. The genesis hash alone is not enough: two nodes can share a genesis and still disagree on emission, epoch length or audit thresholds, which shows up only when they diverge on a later block. Comparing the digest turns that into a refused connection. The seed list is excluded from the digest — adding an entry point is not a consensus change.

Discovery — each node keeps a persistent address book. get_peers / peers exchange addresses, and as long as a node has fewer peers than wanted it dials new ones. On first launch it starts from the network's seed nodes (seeds). Two nodes that dial each other at the same time keep only one connection: the rule — keep the one initiated by the smaller node_id — is the same on both sides, so exactly one survives.

Catch-up — a peer ahead of us gets get_blocks {from, count} and answers blocks, in batches of 128. Every received block is fully re-validated: header, body, state, merkle proof and RandomX. Nothing a peer asserts is taken as given — the pow_hash stored is the one we recomputed.

Relay — the chain notifies its subscribers for every accepted block and every transaction entering the mempool; the network layer announces them to peers. A received block is therefore relayed in turn.

Reorganisations — a block that does not extend the tip is kept in side_blocks. On each new side block, its branch is walked back to an ancestor of our chain and cumulative work is compared. Strictly greater: we switch. On a tie we do not move — first seen keeps the lead.

The switch undoes blocks one by one using the undo journal written with each block (balance and nonce deltas, transaction ids, registry entries), then applies the new branch, re-validating it entirely. All inside a single SQL transaction: if one block of the new branch is invalid, the database returns exactly to its starting state. Dropped blocks are kept aside — their branch may take the lead again later — and their transactions go back to the mempool if they are still valid.

Misbehaviour — faults are graded: a refused transaction is worth 1 point (often just a race), an invalid or unreadable block 25, a malformed message 50. At 100 points the host is set aside for an hour, and the ban is stored, so it survives a restart.

What does not exist yet

  • Mining through a pool requires the template to still be held. The pool returns only the header (aux_blob) on submission, so the body is recovered from the templates table of the node that handed the template out. It survives a restart, but a solution submitted to a node that never issued that template is refused. Once accepted, the block travels over P2P with its body, so this is a constraint on submission, not on propagation.
  • Local RandomX verification: we depend on monerod, which is acceptable since an operator runs one anyway, but it does mean a Symbolon node cannot validate alone.
  • A public network: seed lists are empty and no chain has ever run beyond a local test.
  • Collusion between an operator holding half the registry and four of its five drawn auditors, as quantified above.
