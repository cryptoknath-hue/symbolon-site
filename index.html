The project

Funding the nodes nobody pays

Public Monero nodes are run by volunteers. The ones that matter most for privacy — reachable only over Tor or I2P — are also the most expensive to keep up and the least visible. Symbolon pays them with a currency that costs nothing to produce, because it reuses mining work that has already been done. Three rules frame the idea, and they live in the code rather than in a statement of intent.

Rule 1

Availability, never usage

Paying per request would create a direct incentive to log, classify and attribute user traffic. Probes check that a node answers. Nothing else is observed.

Rule 2

Tor and I2P only

Consensus accepts a .onion v3 or .b32.i2p endpoint and nothing else — a clearnet form is rejected by the network. Subsidising clearnet would fund exactly what Monero defends against.

Rule 3

Collateral, not reputation

Sybil resistance has to cost money, because identity cannot be established without a trusted party. Registering locks a deposit, which a failure eats into.

Mining

Four pieces, one hash

Your miner looks for a RandomX hash for Monero, exactly as it already does. P2Pool slips a merkle tree carrying our block hash into the Monero coinbase. If the hash it finds meets our difficulty, it counts for us too — with no additional computation. No GPU and no ASIC can take part: mining Symbolon is mining RandomX.

Let us be exact about what that does not mean: Symbolon's security is its own difficulty, not Monero's hashrate. The Monero block carrying our proof does not have to be a block Monero accepted — requiring that would make our consensus depend on each node's own view of the Monero chain. Merge mining makes Symbolon free to mine for anyone already mining Monero; it does not transfer Monero's security to it.

An unrestricted monerod

It verifies RandomX for us through calc_pow, and it also verifies proofs of service. Its RPC stays on localhost — never expose it.

A Symbolon node

It answers P2Pool's three merge mining methods on port 19081 and talks to other nodes on 19082.

P2Pool with --merge-mine

P2Pool 4.0 or later. It queries the Symbolon node, inserts our hash into the Monero block and submits solutions to both chains. Any pool can do the same — the interface is generic, and several pools can mine Symbolon at the same time.

Your miner, unchanged

Pointed at P2Pool's stratum, exactly as for mining Monero alone. Nothing more to configure, nothing to install on the miner's side.

# the Symbolon node, delegating RandomX verification to monerod
python3 -m symbolon --network testnet --monerod http://127.0.0.1:28081

# P2Pool mines Monero and Symbolon in the same hash
./p2pool --wallet <XMR_ADDRESS> \
         --merge-mine 127.0.0.1:19081 <SBL_ADDRESS>

Today these commands only work against a local test network.

Get started

A wallet, then a node

Everything below runs against a local test chain. There is no public network to join: what you mine exists only on your own machine, and is worth nothing. That is the point for now — the mechanism can be exercised end to end before anything is launched.

You need Python 3.12 and the cryptography package. Nothing else — no compiler, no database, no build step.

Create a wallet

The wallet asks the node which network it is on and which nonce to use, so start a node first. Leave it running in another terminal. 

# a local node, with a fake proof of work — no monerod needed
python3 -m symbolon --network local --pow sha256 --data-dir /tmp/sbl

# in another terminal: create the key, then look at it
python3 tools/wallet.py new
python3 tools/wallet.py address
python3 tools/wallet.py balance
Back it up now. ~/.symbolon/wallet.json holds your private key in the clear. It is not encrypted, it cannot be regenerated, and losing it loses the coins. Copy it somewhere safe before you mine anything.

Mine

Two ways. The first needs nothing but Python and proves the whole path in a minute. The second is the real thing, against a real Monero daemon and a real P2Pool.

The quick way — a simulated pool

tools/fake_p2pool.py plays P2Pool's side of the three RPC calls against your local node, with a fake proof of work. Blocks arrive in seconds and your balance moves.

python3 tools/fake_p2pool.py http://127.0.0.1:19081 <your sbll address> 3
python3 tools/wallet.py balance

The real way — monerod, P2Pool, your miner

A Monero testnet daemon with an unrestricted RPC, because Symbolon verifies RandomX through calc_pow, which a restricted RPC does not expose. Keep that RPC on localhost.

monerod --testnet --non-interactive \
        --rpc-bind-ip 127.0.0.1 --rpc-bind-port 28081 \
        --zmq-pub tcp://127.0.0.1:28083 --disable-rpc-ban

python3 -m symbolon --network testnet --monerod http://127.0.0.1:28081

./p2pool --host 127.0.0.1 --rpc-port 28081 --zmq-port 28083 \
         --wallet <XMR testnet address> --stratum 127.0.0.1:3333 \
         --merge-mine 127.0.0.1:19081 <your sblt address>

# then point your usual miner at the stratum
xmrig -o 127.0.0.1:3333 -u <XMR testnet address>

On your platform

Two roles, and they are not the same job. Mining needs nothing but a miner pointed at a pool that merge-mines — no new software, no Symbolon-specific anything. Running the stack — a Monero daemon, P2Pool and a Symbolon node — is what takes per-platform setup, and only one person per pool has to do it.

The reference platform — everything here was built and tested on it.

# the node needs Python 3.12 and one library
sudo apt install python3 python3-cryptography

# monerod and P2Pool: official static binaries, no compiler needed
# getmonero.org/downloads · github.com/SChernykh/p2pool/releases
# then the three commands above, and your usual miner on the stratum
xmrig -o 127.0.0.1:3333 -u <XMR address>

Same pieces, official Windows builds for all three. Install Python 3.12 from python.org, ticking Add python.exe to PATH, then run the node from PowerShell. 

pip install cryptography

# monerod: monero-win-x64 zip from getmonero.org
.\monerod.exe --testnet --rpc-bind-port 28081 --zmq-pub tcp://127.0.0.1:28083

# the Symbolon node
python -m symbolon --network testnet --monerod http://127.0.0.1:28081

# P2Pool: p2pool-vX-windows-x64.zip
.\p2pool.exe --host 127.0.0.1 --rpc-port 28081 --zmq-port 28083 `
             --wallet <XMR address> --stratum 127.0.0.1:3333 `
             --merge-mine 127.0.0.1:19081 <SBL address>

# then xmrig, run as administrator so it can use large pages
xmrig.exe -o 127.0.0.1:3333 -u <XMR address>

Running xmrig as administrator is a RandomX matter, not a Symbolon one — without large pages you lose a third of your hashrate on any Monero mining.

A HiveOS rig needs no change at all. It mines RandomX with xmrig against a stratum URL; whether that pool merge-mines is the pool's business, not the rig's. So you do not install anything Symbolon-related on the rig.

Run the stack on a machine you control — a small server, a Raspberry Pi 5, or the same box as your node — and point the flight sheet at it: 

# Flight sheet
Coin           : XMR
Miner          : xmrig
Pool URL       : <the host running P2Pool>:3333
Wallet address : <your XMR address>   # P2Pool pays the wallet it was started with
Algorithm      : rx/0

Expose only the stratum port to your rigs — over a private network or a mesh VPN rather than the open internet. The Monero RPC must stay on localhost: it runs unrestricted, since Symbolon verifies RandomX through calc_pow.

Check that it worked

P2Pool logs uses chain_id … once it has accepted the chain. The node logs a line per accepted block, and your balance is the final word.

python3 tools/wallet.py balance
curl -s http://127.0.0.1:19081 -d '{"jsonrpc":"2.0","id":"0","method":"get_info"}' \
     -H 'Content-Type: application/json'
Step by step

Join the testnet

What runs today, what is still missing before a public network, and the two commands that will change when seed nodes exist.

Tor

Run a service node

The whole procedure for a Tor-only node: one hidden service, collateral, proof of service, and your duties as an auditor. This is the part that needs people.

P2Pool must wait for a fully synced daemon before it starts — it will say monerod is busy syncing until then. The Monero testnet is about 3 million blocks; count a night for a first sync, and minutes to catch up after that.

Proof of service

How to prove a hidden node is there

This is the project's central problem. The availability of a hidden service is a fact that lives off-chain: any report about it is a claim made by whoever probed, and therefore unverifiable. The way out rests on three observations.

1 · Identity

A .onion address is a key

A Tor v3 address is base32(ed25519_key ‖ checksum ‖ version). Consensus extracts the public key and checks the checksum. Nobody can sign in a service's place.

2 · Challenge

The challenge comes from the chain

Keccak256(round_hash ‖ address) picks four consecutive Monero blocks among the last thousand. Unpredictable, identical for everyone, not replayable, and still present on a pruned node.

3 · Verification

Every node checks it again

Every Symbolon node already runs a monerod. It recomputes the expected answer itself, then verifies the signature. Whoever carries the proof has no power over it.

The auditor's nonce changes everything

The challenge is public, so a node could compute it offline and would never need to be reachable at all. That is why the auditor adds its own nonce, anchored to the round's block hash: the answer is bound to that auditor and that draw, and the signature cannot predate that block. Consensus bounds when it was produced.

And that is where the Sybil cost comes from

The answer covers four Monero blocks. One machine can hold the chain once for a thousand identities; it cannot serve it a thousand times, to five auditors each, within the deadline they allow. The cost becomes proportional to the number of identities, without ever needing to know an ASN.

The auditors

Drawn, never chosen

Each round, registered nodes are arranged in a ring by Keccak256(round_hash ‖ address). Everyone audits its five successors, so everyone is audited by its five predecessors. Neither the audited nor the auditor decides, the ring turns every round, and the load is exactly the same for all — nobody is overloaded and nobody is forgotten. That is the animation at the top of this page.

Quorum

Three yes, at most one no

An auditor that cannot reach a node files an absence report, which counts as a duty fulfilled. A round needs three attestations and at most one absence — so three accomplices out of five no longer suffice. Four are needed.

Penalty

Ignoring your draw costs

At each epoch the ring is recomputed over eight sampled rounds. Below 50% of duties fulfilled, 5% of the collateral is burnt — never paid to anyone, so that nobody has an interest in getting another punished.

Diversity

A narrow circle earns nothing

Over an epoch the ring sends an honest node auditors from across the registry. A node attested only by the same small group is paid nothing for availability — which is what makes collusion sterile below half the registry.

Removal

Below the minimum, you're out

If the collateral falls under the threshold, the node leaves the registry and the remainder goes back to its operator. Keeping a struck-off node's deposit locked would protect nothing.

Emission

A tail that never stops

reward = max((18,000,000 SBL − emitted) ≫ 20, 0.35 SBL), plus the block's fees. With one-minute blocks, that 20-bit shift follows Monero's curve in wall-clock time. The tail never stops, and that is the point: a chain whose purpose is to pay for a continuous service cannot stop emitting without ceasing to pay.

Reward per block, over thirteen years

In SBL. The perpetual tail of 0.35 SBL is reached around year eight.

See the values
No premine

Nobody starts ahead

No presale, no founder allocation, no reserved share. The first block is block one.

Service share

+40%, on top

Every 720 blocks the service share is paid: 80% by attested availability, capped at 15% per node, and 20% by audit work performed. It is added to the miner's reward, never taken out of it.

Consequence

18 M is not the final supply

When nodes are being paid, real emission exceeds the target by up to 40%. The 18 M describes the mining curve, not the total. Better said than hidden.

What is not allocated — caps, rounding, no registered nodes — is simply never emitted. No pot accumulates anywhere, so there is nothing to govern and nothing to divert.
